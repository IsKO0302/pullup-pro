# PROJECT_ROADMAP — PULLUP PRO

Что делать дальше, по убыванию ценности. Каждый пункт — отдельная контрольная точка (тест → документация → коммит).

## 1. Запуск в Telegram (нужны действия владельца)

1. @BotFather → `/newbot` → токен в `.env` (`TELEGRAM_BOT_TOKEN`), username (`TELEGRAM_BOT_USERNAME`).
2. Публичный HTTPS: Caddy-профиль `docker compose --profile https` или хостинг (см. docs/DEPLOYMENT.md). `APP_BASE_URL`/`TELEGRAM_WEBAPP_URL` — этот адрес.
3. Menu Button / Main Mini App в BotFather; запуск бота — он сам регистрирует команды и кнопку.
4. Проверка на реальных клиентах Telegram: Android, iOS, Desktop (safe area, fullscreen, BackButton/MainButton, тема).
5. Проверка установки PWA на Android/iOS.

## 2. i18n — продолжение (основа готова)

Готово: движок `packages/shared/src/i18n` (словарь «русская строка → перевод», `{a}`–`{h}` = одно слово-значение, `{x}` = фраза), перевод DOM на лету (`apps/web/src/core/i18n.ts`), язык дат/чисел/множественных форм, словари EN/TR (≈2800 строк: интерфейс, каталог упражнений, программы, Muscle-Up, подписи анимации), переключатель, определение языка, бот. Измерение: `node tests/qa/i18n-coverage.mjs <url> en|tr out.json` (русские остатки на всех экранах) + статический поиск русских литералов в коде; e2e `tests/e2e/i18n.spec.ts` проверяет 20 экранов и карточек.

Осталось:
1. Редкие состояния интерфейса: ошибки и состояния синхронизации, часть тостов, диалоги импорта (в коде ещё ≈ 600–900 литералов, которые не видны при обычной работе) — найти статическим поиском и дополнить словарь.
2. Динамические сообщения бота (/today, /stats, /progress, /reminder): строятся общими форматтерами с глобальным языком — нужен язык на пользователя.
3. Проверка носителем турецкого языка: переводы сделаны без носителя (термины зала оставлены латиницей там, где так принято: dips, deload, face pull, false grip).
4. Добавление нового текста: новая русская строка в коде автоматически попадает в список остатков (`i18n-coverage.mjs`); перевод — в `packages/shared/src/i18n/en-N.ts` / `tr-N.ts`.
## 3. Качество и надёжность

- Docker: собрать образы, прогнать `docker compose up` (на машине разработки Docker не установлен).
- Автоматический прогон тестов в CI (GitHub Actions): typecheck, unit, integration (сервис PostgreSQL), e2e.
- Резервные копии PostgreSQL по расписанию (сценарий в docs/DEPLOYMENT.md описан, автоматизации нет).
- Шифрование облачных фото на стороне клиента (см. docs/SECURITY.md, «Известные ограничения»).
- Типизация перенесённых из 1.0 экранов `apps/web` (убрать явные `any`).
- Разбить файлы больше 800 строк (`settings.ts` ≈ 46 КБ, `train.ts` ≈ 46 КБ, `figure.ts` ≈ 66 КБ).

## 4. Продукт

- Реальные фотографии/видео техники к упражнениям (сейчас — SVG-анимации).
- Приватные сравнения «до/после» с экспортом изображения.
- Недельный отчёт в Telegram с графиком-картинкой.
- Режим нескольких профилей на одном устройстве.
- Режим тренировки (`apps/web/src/features/workout/train.ts`, строки 168 и 204): плитка «Подтягивания» всегда показана, даже в тренировке без тяги (показывает 0) — заменить на показатель, зависящий от группы мышц тренировки.
- Уведомления о достижениях и целях в боте (инфраструктура напоминаний есть).

## 5. Хостинг (только с согласия владельца)

Сравнить актуальные условия на момент выбора (не обещаем «бесплатно» без проверки): VPS (Hetzner, Timeweb и т.п.) с Docker Compose; PaaS (Fly.io, Railway, Render); управляемый PostgreSQL (Neon, Supabase, Timeweb Cloud). Требования: HTTPS, PostgreSQL 14+, один процесс Node 22+.
