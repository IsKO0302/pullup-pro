# Аудит версии 1.0, резервная копия и перенос в 2.0

## 1. Исходное состояние PULLUP PRO 1.0

| Параметр | 1.0 |
|---|---|
| Поставка | Один файл `PULLUP-PRO-v1.html` (≈377 КБ), собранный `build.py` из 19 глобальных скриптов `src/js/*.js` и `style.css` |
| Код | Глобальные функции и переменные без модулей, типов и тестов |
| Данные | Только `localStorage` под ключом `pullup.pro.v1`; экспорт/импорт JSON, генератор демо-данных |
| Экраны | Главная, программы, тренировка, журнал, статистика, календарь, конструктор, библиотека, выход силой, настройки |
| Каталог | 36 упражнений, 3 программы подтягиваний (beginner / intermediate / advanced), 36 достижений |
| Нет | Service worker и манифеста (нет установки и офлайн-гарантий), сервера и синхронизации, Telegram, фото прогресса, замеров тела, питания, напоминаний |

## 2. Резервная копия (неизменяемая)

`legacy/v1/` — оригинальные файлы 1.0, в 2.0 они не изменяются:

| Файл | SHA-256 |
|---|---|
| `PULLUP-PRO-v1.html` | `98fc5b76790a6470f0a9c75fa9f62bda2c19e5463026a3518c6a59ec748151b1` |
| `pullup-pro-v1-source.zip` | `6a4776edc8251740c1660960f9c886ef2b99b708ea846eb2a1acdea4bb3b83e3` |

Проверка целостности: `cd legacy/v1 && sha256sum -c SHA256SUMS`.

`legacy/v1/figure.v1.ts` — модуль анимированной фигуры 1.0 после автоматической конвертации, до переработки анимаций в 2.0; хранится для сравнения и в сборку не входит.

## 3. Перенос кода

- `scripts/migration/legacy-analyze.mjs` — список верхнеуровневых объявлений каждого файла 1.0 для плана разбиения на модули.
- `scripts/migration/legacy-convert.mjs` — одноразовая конвертация глобальных скриптов в ES-модули: каждое объявление экспортируется, импорты строятся по перекрёстным ссылкам.
- `scripts/migration/legacy-typefix.mjs` — явные `any` для динамических объявлений, чтобы перенесённые экраны проходили `tsc` без изменения поведения.
- Чистая логика (каталог, статистика, миграция, синхронизация, валидация) вынесена в `packages/shared` с типами и юнит-тестами; экраны — в `apps/web/src/features/*`.

## 4. Перенос данных пользователя

- При первом запуске 2.0 данные из `pullup.pro.v1` **только читаются**, переводятся функцией `migrateState` (`packages/shared/src/migrate.ts`) в формат `STATE_VERSION = 2` и сохраняются под новым ключом `pullup.pro.v2`. Ключ 1.0 не изменяется и не удаляется — к версии 1.0 можно вернуться с исходными данными.
- Сохраняются все записи, идентификаторы и поля 1.0; повреждённые структуры восстанавливаются, а не сбрасываются; ключи prototype pollution игнорируются; файлы, не являющиеся резервной копией, отклоняются.
- Новые коллекции 2.0 (тело, фото, питание, напоминания, движок) получают безопасные значения по умолчанию.
- Импорт резервной копии JSON 1.0 доступен в настройках; перед импортом, сбросом, демо-данными и восстановлением создаётся снимок безопасности с возможностью отката.
- Проверка на реальных данных: `scripts/fixtures/make-v1-backup.mjs` запускает **оригинальное** приложение 1.0 из `legacy/v1`, проходит его онбординг, генерирует демо-данные встроенным генератором 1.0 и экспортирует их кнопкой 1.0 → `tests/fixtures/v1-backup.json` (31 тренировка). Эту копию импортируют юнит-тесты (`tests/unit/migrate.test.ts`) и e2e-тест (`tests/e2e/data.spec.ts`: журнал, статистика, календарь, достижения после импорта), а e2e-тест синхронизации переносит её через сервер на второе устройство и в бота.

## 5. Что сохранено из 1.0

- Все экраны и сценарии 1.0, тёмная фирменная тема, три программы подтягиваний 1.0 (раздел «Подтягивания (программы 1.0)» в настройках), 36 упражнений с прежними id (дополнены техникой, ошибками и дозами), 36 достижений, путь к выходу силой, конструктор, календарь, журнал, экспорт и импорт JSON.

## 6. Что изменено и добавлено

Полный список — в [CHANGELOG.md](../CHANGELOG.md). Кратко: модульная архитектура на TypeScript, каталог 85 упражнений и 7 новых программ, движок тренировок с прогрессией по подтверждению, персонализация из 7 шагов, тело и фото, питание, недельный отчёт, PWA с офлайн-режимом и безопасными обновлениями, Telegram Mini App и бот, синхронизация между устройствами, PostgreSQL, тесты и документация.

## 7. Ошибки, найденные при проверке 2.0 и исправленные

| Где | Проблема | Исправление |
|---|---|---|
| PWA, обновление | Перезагрузка по `controllerchange` срабатывала и при первой установке service worker (лишняя перезагрузка на первом запуске), а у кнопки «Обновить» не было запасного пути, если событие не приходило | `controllerchange` учитывает, был ли контроллер; перезагрузка только при смене версии, плюс резервная перезагрузка через 4 с после «Обновить» (`apps/web/src/services/pwa.ts`) |
| Офлайн-значок | На широких экранах значок «Офлайн» был только в шапке, скрытой при боковом меню | Значок добавлен в боковую панель, обновляются все `.net-badge` |
| Адаптивность | На ширине 1024 px длинные названия в чипах и элементы сетки раздвигали страницу (`#/library/pullup`) | Переносы в чипах (`a.chip`), `min-width: 0` для элементов `.grid` |
| Питание, 390 px | Кнопка «Включить дневник питания» выходила за край карточки | Блок текста переносится под иконку, кнопка не шире карточки |
| Программы, 320 px | Значки «Текущая» / «Рекомендуем» и длинные цели программ выходили за карточку | Перенос шапки карточки и длинных значков |
| Статистика, телефон и компьютер | Значение «Время» (например, «23 ч 47 мин») обрезалось многоточием — на телефоне и на ширине 1366–1440 px | Для значений 9–12 символов — средний размер шрифта и перенос на вторую строку вместо многоточия |
| Отчёт недели, 390 px | Значок «3/3 цель выполнена» сжимался до узкой полоски, подпись выходила за рамку | На узких экранах значок занимает отдельную строку под именем, число и подпись — в одну линию |
| Настройки, телефон | Текст «Сейчас загружены ДЕМО-данные…» сжимался кнопкой «Вернуть мои данные» до одного слова в строке | Кнопка переносится под текст (класс `.note-act`) |
| Открытие с диска | `apps/web/dist/index.html`, открытый двойным щелчком, показывал только ссылки без оформления: браузеры не загружают модульные скрипты на `file://` | Версия в одном файле `npm run build:single` (без сервера), в README — какая сборка для чего |
| Service worker | Изменение только кода service worker не меняло версию кэша; комментарий обещал фоновое обновление оболочки, которого нет | Версия считается и от шаблона service worker; комментарий приведён в соответствие с кодом |

Ошибки вёрстки ловит `responsive.spec.ts` (выход элементов за экран, карточку, плитку и подсказку, сжатый кнопкой текст, обрезанные значения KPI — на 8 ширинах от 320 до 1920 px), открытие с диска — `single-file.spec.ts`, обновление — `pwa.spec.ts`; см. [TESTING.md](TESTING.md).
